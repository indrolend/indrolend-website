# Particle System Documentation

## Overview

The Indrolend website features a sophisticated particle system inspired by the [Proton particle engine](https://github.com/drawcall/Proton), optimized for web performance while maintaining visual appeal and interactivity.

## Architecture

### Core Components

#### 1. Particle Engine (`js/particle-engine.js`)
A modular, reusable particle system engine that provides:

- **Span**: Flexible value range utility for randomization
- **Particle**: Individual particle with lifecycle management
- **ParticlePool**: Object pooling for efficient memory usage
- **Behavior System**: Pluggable behaviors for particle effects
- **Emitter**: Particle generation and management
- **ParticleEngine**: Main engine coordinating multiple emitters

#### 2. Background Particles (`js/script.js`)
Animated text-based particles that form the homepage background:

- 60 particles with random alphanumeric characters
- Mouse repulsion and grab interactions
- Snake game integration (Easter egg)
- Connection lines between nearby particles
- Character morphing at random intervals

#### 3. Social Media Button Clusters (`js/particle-clusters.js`)
Platform-specific particle clusters for interactive buttons:

- 25 particles per button (optimized for performance)
- Brand-colored particles matching each platform
- Mouse repulsion with spring-back physics
- Intersection Observer for visibility optimization
- Special rainbow explosion for unlocked gallery

#### 4. Game Particles (`js/easter-egg.js`)
Dynamic particles for interactive games:

- Cube physics with 3D-like rendering
- Snake game with particle transformation
- Tic-tac-toe with particle-based visuals

## Key Concepts from Proton

### 1. Emitter Pattern
Particles are generated by emitters, which control:
- Emission rate (particles per second)
- Initial position and velocity
- Particle properties (size, color, lifetime)

### 2. Behavior System
Modular behaviors that can be applied to particles:
- **AlphaBehavior**: Fade particles over lifetime
- **GravityBehavior**: Apply gravity force
- **AttractionBehavior**: Pull particles to a point
- **RepulsionBehavior**: Push particles away from a point
- **SpringBehavior**: Return particles to original position

### 3. Object Pooling
Efficient memory management through particle recycling:
- Pre-allocate particles to avoid garbage collection
- Reuse particles instead of creating/destroying
- Significantly reduces memory pressure

### 4. Separation of Concerns
Clean architecture with separated responsibilities:
- Particle logic separate from rendering
- Configurable behaviors
- Extensible emitter system

## Performance Optimizations

### 1. Distance Calculations
```javascript
// Use squared distance to avoid expensive sqrt()
const distSq = dx * dx + dy * dy;
if (distSq < radiusSq) {
  const distance = Math.sqrt(distSq); // Only when needed
  // ... apply force
}
```

### 2. Early Returns
```javascript
// Skip processing for inactive or off-screen particles
if (!particle.active || particle.x < 0) return;
```

### 3. Object Pooling
```javascript
// Reuse particles instead of creating new ones
const particle = this.pool.get();  // Get from pool
// ... use particle
this.pool.release(particle);       // Return to pool
```

### 4. Batched Rendering
```javascript
// Set context state once, then draw all particles
ctx.fillStyle = particleColor;
particles.forEach(p => ctx.fillText(p.char, p.x, p.y));
```

### 5. Intersection Observer
```javascript
// Only animate particles when visible on screen
const observer = new IntersectionObserver((entries) => {
  isVisible = entry.isIntersecting;
  if (isVisible) animate();
  else cancelAnimationFrame(animationId);
});
```

### 6. Velocity Limiting
```javascript
// Prevent particles from moving too fast
const speedSq = vx * vx + vy * vy;
if (speedSq > maxSpeedSq) {
  const speed = Math.sqrt(speedSq);
  vx = (vx / speed) * maxSpeed;
}
```

## Usage Examples

### Basic Particle Emitter
```javascript
const emitter = new Emitter();
emitter.x = 100;
emitter.y = 100;
emitter.rate = 10; // 10 particles per second
emitter.radiusSpan = new Span(2, 5);
emitter.lifeSpan = new Span(2, 4);
emitter.velocitySpan = new Span(-2, 2);

// Add behaviors
emitter.addBehavior(new AlphaBehavior(1, 0));
emitter.addBehavior(new GravityBehavior(0.1));

// Create engine and start
const engine = new ParticleEngine();
engine.addEmitter(emitter);
engine.start();
```

### Custom Behavior
```javascript
class CustomBehavior extends Behavior {
  apply(particle, dt) {
    // Custom logic here
    particle.vx += Math.sin(particle.age) * 0.1;
  }
}

emitter.addBehavior(new CustomBehavior());
```

### Rendering to Canvas
```javascript
function animate() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  engine.update();
  engine.draw(ctx);
  requestAnimationFrame(animate);
}
```

## Best Practices

### 1. Limit Particle Counts
Keep particle counts reasonable for target devices:
- Desktop: 50-100 particles
- Mobile: 20-30 particles
- Low-end: 10-15 particles

### 2. Use Object Pooling
Always use pooling for frequently created/destroyed particles:
```javascript
const pool = new ParticlePool(100);
const particle = pool.get();  // Reuse
pool.release(particle);       // Return
```

### 3. Optimize Distance Checks
Use squared distances when possible:
```javascript
const distSq = dx * dx + dy * dy;
if (distSq < radiusSq) {
  // Only calculate sqrt when necessary
}
```

### 4. Batch Similar Operations
Group similar rendering operations:
```javascript
// Good: Set state once
ctx.fillStyle = color;
particles.forEach(p => ctx.fillRect(p.x, p.y, 2, 2));

// Bad: Set state repeatedly
particles.forEach(p => {
  ctx.fillStyle = color;
  ctx.fillRect(p.x, p.y, 2, 2);
});
```

### 5. Use Visibility Checks
Don't animate off-screen particles:
```javascript
if (particle.x < 0 || particle.x > canvas.width) return;
```

## Troubleshooting

### Low Frame Rate
- Reduce particle count
- Disable particle-to-particle interactions
- Reduce connection distance
- Use simpler behaviors

### High Memory Usage
- Ensure object pooling is enabled
- Check for memory leaks (particles not being released)
- Reduce pool size if not needed
- Clear unused emitters

### Particles Not Appearing
- Check canvas dimensions
- Verify emitter position is within canvas
- Ensure particle lifetime is sufficient
- Check if Intersection Observer is working
